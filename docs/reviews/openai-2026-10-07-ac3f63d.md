Blocker, lib/redmine_view_issue_description/patches/issues_controller_patch.rb:58-71
Self-assignment bypass via assigned_to_id=me in bulk_update is not blocked. The check in vid_authorize_self_assignment only considers numeric IDs and the 'none' sentinel. In Redmine, bulk update can submit assigned_to_id='me' from the UI. With 'me', assignee = Principal.find_by(id: 'me'.to_i) becomes nil and the guard returns early, letting the self-assignment proceed. The user then becomes assignee and can open the issue, defeating the protection.
Concrete failure: A project member with edit_issues but without view_issue_description uses the context menu on an issue they cannot open and selects Assignee = me. POST /issues/bulk_update with issue[assigned_to_id]=me succeeds, assigns the issue to the user, and they can now read its description via show/API. Your tests only cover numeric IDs and miss this path.
Fix: Normalize 'me' to the current user before the Principal lookup and apply the same prohibition:
  assignee_val = params.dig(:issue, :assigned_to_id).to_s
  return if assignee_val.blank? || assignee_val == 'none'
  user = User.current
  principal_id = (assignee_val == 'me') ? user.id : assignee_val.to_i
  assignee = Principal.find_by(id: principal_id)
  return unless assignee && user.is_or_belongs_to?(assignee)
  render_403 if @issues.any? { |issue| !issue.detail_access_granted?(user) }
